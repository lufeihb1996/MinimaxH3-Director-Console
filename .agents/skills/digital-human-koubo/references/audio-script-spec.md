# 口播配音稿规范

仅约束 Fish Audio Drama 3 的 `script_text`。建项、审核、音频分析和带词建镜的顺序由[口播 Skill](../SKILL.md)维护，不在这里重复。

## 输入格式

- 每行一句，行首写 `<|speaker:N|>`，N 从 0 连续编号，对应任务里的音色绑定；当前工作台支持 0–15。
- 同一说话人连续多句也逐行重复标签；不要插入空白分隔、Markdown 标题或导演旁白。
- 每行用中文句末标点结束，一行只放一个完整句子；两个句子分两行，避免过去出现的超长停顿。
- 表演信息通过实际支持的情绪标签表达，不写“（停顿）”“镜头切近景”等可能被读出的说明。
- 本项目已有使用记录的标签包括 `[sighs]`、`[chuckles]`、`[giggles]`、`[excited]`，每行先控制在一个，紧跟说话人标签；其他标签先核对当前模型支持，不能凭空断言支持或不支持。
- 数字优先写成所需读法的汉字，如“七成五”“两百英里”；保留用户明确要求的语言和专名。

格式示意：

```text
<|speaker:0|>为什么这件事情，会突然变成大家关注的焦点？
<|speaker:1|>[excited]关键是这次变化，让原来的判断条件完全不同了。
```

## 分句与内容

- 既有项目常用每行 14–32 字、优先 18–28 字作为起点；主持人问题尽量不超过 22 字。它们是写稿建议，不是模型硬上限或真实音频秒数。
- 一行只推进一件事，长句在自然气口拆分；不要为了字数把不同说话人拼成一行。
- 用具体数字、动作和场景解释观点，按正常说话方式写；减少书面连接词和反复总结。
- 访谈需要交代主持人、嘉宾和话题，并自然收尾；约 90 秒的解读可参考“钩子→反常识→机制→方法→落点”，不强套所有题材。
- 配音前的字数估算不能用作分镜切点。生成后的短句可能合并、长句可能拆镜；换说话人的模式由口播流程显式规划。

## 时长估算

可先按中文约 4.6 字/秒、句间留气口估算；实际时长以音频为准。

| 目标时长 | 起稿字数参考 |
|---|---|
| 30 秒 | 130–145 |
| 60 秒 | 260–285 |
| 90 秒 | 390–420 |
| 120 秒 | 520–560 |

## 音频验收

- 试听台词是否完整、角色音色是否对应、标签是否被念出，有无读错数字和专名。
- 项目曾出现单行多个句子带来约十秒静音的失败；无意图的连续静音超过 2 秒时，检查对应行和情绪标签，修稿或剪辑后重新分析，不直接建镜。
- 约 0.8–1.2 秒气口是既有素材参考，不能当成每句固定要求；全片静音占比很高时检查节奏。
- 对齐后逐行检查 `aligned_ratio == 1.0`，并核对缺字、切点与停顿。自动分析通过不能替代试听。

保存前逐行核对说话人、句末标点、情绪标签、数字读法和分句；字数检查不能代替实际音频验收。
