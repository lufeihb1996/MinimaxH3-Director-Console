# 制作流程 — 从空项目到成片

[English](WORKFLOW.md) | [简体中文](WORKFLOW.zh-CN.md)

本文按界面真实顺序写。除第 1、5、6、8 步外，其余都可以跳过。

```
1 项目/场景 → 2 参考图 → 3 音频（歌曲/MV）→ 4 配音
→ 5 分镜 → 6 生成 → 7 选版本 → 8 合并 → 9 口播包装（可选）
```

---

## 1. 项目与场景

**Project** 管 Scene，**Scene** 管 Shot。一个 Scene 通常对应一个地点或一段连续动作。

- 左上角 `＋` 新建项目。
- 左侧栏在 **视频导演台 / 生图工作台 / 音频工作台 / 配音工作台 / 口播包装台** 之间切换，五个工作台操作的是同一个项目。
- **新建场景** 添加 Scene；之后创建的分镜会继承它的参考图。

这一步只往 `data/studio.db` 写数据，不会触发生成。

## 2. 参考图（生图工作台）

每个 Scene 固定四个槽位：

| 槽位 | 用途 |
|---|---|
| Ref1 | 主角 |
| Ref2 | 配角 |
| Ref3 | 场景 A |
| Ref4 | 场景 B / 道具 |

- 选生图模型（默认 `moss_image_5b`，也可 `krea2`）、比例和提示词，点 **生成**；也可以直接**上传 / 拖拽 / Ctrl+V 粘贴**。
- 每次结果都进该槽位的**历史图**；只有点 **应用** 的那张才会成为后续 CUT 的默认图。
- Ref1/Ref2 有**作用域**开关：*场景*（默认）或 *项目*。选项目时同一张人物图跨 Scene 共享，只生成一次。
- 可以一次把多个槽位加入生图队列；生图队列与视频队列相互独立。

做 T2V 镜头可以完全跳过这一步——它不需要任何参考图。

## 3. 音频（歌曲 / MV / 口播）

**音频工作台**做两件事：

- **YuE2 歌曲**：填风格和歌词，点 **生成歌曲**。一个项目只保留一首，没有历史版本。
- **上传音频**：用自己的音轨（MV、旁白、对白）。

两种来源都要再点 **分析**。分析产物：

| 产物 | 用途 |
|---|---|
| `vocals.wav` / `no_vocals.wav` | Demucs 分离结果，MV 用纯人声驱动口型 |
| `timeline.json` | 切点、节拍、每句台词的时间 |
| `lyrics.srt` | 合并时压进成片的歌词字幕 |

分析跑在独立的 `audio_analysis/` 环境里（见 README）。没装这个环境时本步失败，音频相关功能全部不可用，但生图和视频照常。

替换音频会让旧的分镜时间失效。**先把最终音频定下来，再规划分镜。**

## 4. 配音（数字人 / 访谈）

**配音工作台**：

1. 点 `＋ 添加队列` 建一条任务。
2. 给每个说话人挑一个**音色**（全局音色库，跨项目复用）。
3. 写剧本。多人时用 `<|speaker:0|>`、`<|speaker:1|>` 标记每行归属。
4. 点 **生成配音**（Fish Audio Drama 3），完成后可以 **设为项目音频**。

如果项目还没有音频，生成完成后会自动挂上去；如果已经有歌曲或外部音轨，必须明确确认替换。

情绪标签如 `[sighs]`、`[laughs]`、`[whispers]` 直接写在台词里。

## 5. 分镜

两种建法：

- **新建分镜**：一条一条手动加。
- **按音频自动分镜**：读分析好的时间轴和人声谷底，给出切点方案。预览是 dry run，不点确认不会写库；如果预览和保存之间方案变了，接口返回 `409 PLAN_CHANGED`，必须重新预览。

每个镜头要定：

| 字段 | 说明 |
|---|---|
| 模式 | `T2V`（只吃提示词）、`CUT`（吃参考图）、`CONTINUE`（接上一镜末帧） |
| 视频模型 | `b15_49`（ComfyUI）或 `pika_h3`（独立服务） |
| 比例 / MP / 步数 / Seed | 受 `config/models.json` 约束 |
| 二采 | 仅 `b15_49`：0.4MP 一采后再做 720p / 1K / 1.5K / 2K 精修 |

`CONTINUE` 会等同 Scene 的上一镜完成，自动提取它的末帧；也可以手动指定首帧覆盖。

## 6. 生成

三种范围：**单镜**、**整个场景**、**整个项目**。

- 入队时会把该镜的参数和素材冻结到 `projects/project_NNN/scene_NNN/shot_NNNN/inputs/<id>/`，之后改参数不影响已排队任务。
- 后端用单一 GPU 槽位串行调度，只在模型 key 变化时才调 ComfyUI `/free`。
- 进度通过 WebSocket 推送；终端面板显示当前镜头的 ComfyUI / Pika 日志。
- 开了二采时，重跑场景会重新排队所有非运行中的镜头，包括已经是 `DONE` 的。

## 7. 选版本

每次生成都存成 `shot_NNNN_v1.mp4`、`v2`……失败不会删旧版本：旧成片保持选中，失败信息记在旁边。

点版本即可选中，合并用的是选中的那一版。

## 8. 合并

- **播放本场景**：合并当前 Scene 已完成的镜头。CONTINUE 接缝会做处理（重复静止帧、低频明暗与色度漂移、静止背景微融合），运动区域不做整帧叠化。
- **合并全剧**：统一画布尺寸和帧率后拼接各 Scene，把原音轨合回去；MV 项目会压制歌词字幕。

产物都在 `projects/project_NNN/`：

| 文件 | 内容 |
|---|---|
| `project_NNN_master_no_subtitles.mp4` | 无字幕合并版 |
| `project_NNN_master.srt` | 生成的歌词字幕 |
| `project_NNN_master.mp4` | 最终成片 |
| `scene_NNN_master.mp4` | 单个场景的成片 |

合并有缓存：输入没变就复用上次结果。

## 9. 口播包装（可选）

**16:9 口播包装台** 把口播片段做成卡片式横屏视频：浏览器里改卡片文字、即时预览，走 Remotion 渲染导出 MP4。

```
│ 项目列表       │ 分镜列表 / 编辑器                      │ 参考图槽位       │
│  └ 场景        │  模式、模型、提示词、台词               │  Ref1..Ref4     │

```

顶栏：工作台切换、项目切换、设置（`comfy_url`、`pika_url`、`fps`）。

## 值得记住的规则

- 已入队的任务参数是冻结的；想改就先等它跑完，否则改动会留到下一次。
- 重新生成失败不会清掉上一次成功的成片。
- 上传或替换项目音频会让之前的分镜时间失效，改完要重新规划。
- 应用不会猜远端能力：不支持的组合（例如 Pika + MV 原声锁定）会在入队前直接报错，而不是静默降级。
